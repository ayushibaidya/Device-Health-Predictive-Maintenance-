# Synthetic CPU and memory observations

Synthetic troubleshooting guidance for this project's simulator, not operating
system diagnostics. Source-checked against baseline `2b919b7`.

## What the readings mean

`cpu_utilization_pct` and `memory_utilization_pct` are generated from hidden
degradation plus bounded noise, then clamped to 0–100 percent. They do not measure
a process, host CPU scheduler, allocation rate or real memory consumption.

These metrics are correlated symptoms produced by the simulation. They do not
feed back into degradation or the health-state transition rules. No CPU or
memory percentage threshold independently triggers the current alert rule.

## Investigation checks

- Compare actual CPU and memory samples within the selected device/run window.
  State whether both move together or whether only individual noisy samples vary.
- Check timestamps and accepted order before describing a trend; do not join
  samples from different runs into a continuous trace.
- Relate observations to the simulator-reported state and cite the readings.
  Report limited coverage when the five-minute window omits earlier behavior.

## Limits

The evidence cannot establish a memory leak, a runaway process, thread
contention or resource exhaustion. Do not prescribe process termination or
memory replacement as a diagnosis. Optional actuator fields accepted by the
validator are not generated by the current simulator and must not be invented.
